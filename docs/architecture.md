# 架构说明

采用 Windows 原生 AutoHotkey v2，单进程、模块化、轻量常驻。P1 已实现常驻、配置和托盘；P0 系统模块提供独立诊断。输入功能和自动监听分别在 P2/P4 接入。

| 目录 | 职责 | 计划阶段 |
| --- | --- | --- |
| `main.ahk`、`src/App.ahk` | 入口、生命周期、功能协调 | P1 已实现；功能协调后续扩展 |
| `config`、`src/config` | 示例配置、默认值、读取与保存 | P1 |
| `src/common` | 日志、通知、文本规则 | P1/P2 |
| `src/system` | 窗口、IME、剪贴板、发送与权限 | P0/P2/P3 |
| `src/features` | 重喂/取回、自动切换编排 | P2/P4 |
| `src/rules` | 有序纯规则匹配 | P3 |
| `src/ui` | 托盘与基础设置 | P1/P5 |
| `tests` | 纯逻辑测试、手动验收、真实兼容结果 | 随功能维护 |
| `docs` | 架构和使用说明 | 随功能维护 |

实现顺序为：IME 诊断与控制 → 常驻与配置 → 重喂/取回 → 规则 → 自动切换 → 设置/试用 → 打包。独立模块可以先自动验证，环境受限时真实桌面验证延后至 UAT。

ConfigStore 严格解析 INI，保留规则顺序，非法现有文件不重置；保存前校验，在同目录写完临时文件再替换。App 在加载候选配置并完成热键注册后才更新有效配置。HotkeyBindings 在部分注册失败时回退，暂停及退出统一注销绑定；可注入驱动用于故障测试。Logger 仅存有界的内存诊断，不记录输入内容。当前 App 没有输入功能处理器，因此不会注册它们的热键，也没有轮询定时器。

输入法种类与内部模式分开处理：重喂允许激活指定搜狗；自动规则只调整当前受支持中文输入法的内部模式。选词归输入法与用户，撤销归应用，取回原文只提供单条内存缓存兜底。

更多接口、行为及验收见 [PLAN](../PLAN.md)，当前状态见 [ROADMAP](../ROADMAP.md)。
