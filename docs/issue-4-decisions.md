# Issue #4 决策、实施与验收

更新：2026-10-05。依据：用户在对话中确认的四项决策及 [Issue #4 最新反馈](https://github.com/ziyumieming/Ime-2Chinese/issues/4#issuecomment-5981659727)。本轮完成改造并自动验证，真实桌面 UAT 待做。本文取代早期计划中有关自动切换推进、输入位置监听及诊断内容的相应约定。

- 窗口自动切换停止后续开发，保留已实现的 RuleEngine、AutoSwitchFeature、历史显式测试入口及回归测试；不新增输入框规则或独立规则文件。
- 移除托盘的规则/配置文件编辑入口和自动切换开关，移除设置窗口的规则入口、自动切换开关及窗口检查间隔；删除规则示例。普通偏好通过设置窗口修改。
- 已有用户配置及其规则保持兼容，保存可见设置不改写隐藏偏好；不删除本机旧规则、不改造历史自动切换算法。历史 `--test-all` 入口原有的定时检查仍保留，只供已有实现的回归。
- 重喂继续采用全局热键触发后检查。普通入口及 `--test-refeed` 不增加轮询、焦点事件订阅或后台可编辑状态缓存；无效场景仍可能吞掉本应用已绑定的组合键，接受这一行为，不自动补发按键。
- P6 打包暂缓；下面两个待办已实现。设置只保留窗口入口，托盘仅暂停、设置、诊断及退出。

## 待办 A：重喂与取回的可编辑位置检查

**状态：代码及自动验证完成，桌面待 UAT。** 在复制、切换输入法、删除和发送前检查操作目标；实际发送前复核目标未变化。Edit/RichEdit 检查 enabled、ES_PASSWORD、ES_READONLY；UIA 检查进程、控件类型、密码、可用状态及 ValuePattern/TextPattern 的只读元数据，不要求必须支持 ValuePattern。未知/混合属性不猜测；保留焦点元素引用复核同一位置，不读取其文本。

| 场景 | 重喂 | 取回原文 |
| --- | --- | --- |
| 可编辑、存在非空选区 | 通过位置检查后沿用文本/输入法检查 | 原样插入缓存，允许替换选区 |
| 可编辑、无选区 | 静默结束，不发送复制，不切换模式 | 可在光标处插入缓存，不要求选区 |
| 网页正文或只读区域 | 静默结束，不复制、不切换、不删除或发送 | 静默结束，不插入 |
| 密码框、目标禁用或无法确认可编辑 | 静默结束，记录检查结果 | 静默结束，记录检查结果 |
| 检查后换窗或换输入位置 | 停止，沿用已有焦点及缓存保护 | 停止，不发送到新目标 |

不得仅凭 TextPattern、有选区、有光标或输入法开启判定可编辑。原生 Edit/RichEdit 检查只读及可用状态；其他控件结合 UIA 文本/值接口与控件信息判断。不能要求所有目标必须支持 ValuePattern，避免排除多行文本或浏览器可编辑内容。无法判定时跳过。

验收覆盖可编辑单行/多行框、浏览器输入框与 contenteditable、网页正文选区、只读框、密码框、空选区、无缓存取回、同窗焦点变化；无效请求不改变剪贴板、模式、文本或已有原文缓存。应用快捷键是否被吞掉与是否执行重喂分别记录。

## 待办 B：面向排错的诊断改造

**状态：代码及自动验证完成，桌面待 UAT。** 记录一次操作的过程，而不只记录最后的事件编号。

- 每次操作具有关联编号，记录阶段、起止时间/耗时、结果与失败原因。阶段包括目标/可编辑检查、选区、复制、模式确认、稳定等待、删除、发送及取回。
- 记录目标进程、完整窗口标题、窗口/焦点身份、可编辑/只读/密码/禁用判断及读取失败；记录输入布局、IME 原始 open/conversion 值、请求模式和读回模式。
- 记录选区长度、已取得的选中文本、实际发送字符数、剪贴板归属/序列检查、是否尝试删除、原文缓存是否可用及底层错误码/异常位置。截断文本必须明确标记，数据与记录总量有界。
- 用户已允许记录选中文本和完整窗口标题。只记录操作中已经取得的选区；不为诊断额外复制、不扫描整个输入框或剪贴板、不记录密码内容。
- 易读窗口给出失败阶段和操作后果，详细字段可查看；无法确定根因时显示观察结果，不伪称已找到原因。
- 新记录以事件/回调通知可见诊断窗口，合并连续更新；窗口关闭后不刷新。不得为诊断实时更新增加轮询计时器。
- 提供主动导出当前快照：UTF-8 文本，包含可读概况、版本/运行入口及各操作的详细字段。仅用户主动导出时写文件；不自动持久化或上传诊断内容。
- 连续重复结果保留首次/末次时间及次数，操作分组不能被高频步骤挤掉。清空记录不清空原文缓存，也不改变输入法或配置。

容量：最多 30 组事件/操作，每组 64 个步骤，每步最多 40 个字段；选中文本上限 4096 字符、标题 32768、其他字符串 2048，超过时标记原长度及截断。完全相同目标/内容/结果的连续操作合并，保留首末时间、操作编号及次数，显示最近一次过程；不同内容不合并。发送数指已完成的发送调用数，不是应用已上屏的证明。UIA elementReference 是本次持有的 COM 引用标识，不当作跨操作稳定 ID。

诊断通过订阅回调及合并的窗口消息更新，隐藏时退订，退出时移除回调；不使用刷新计时器。导出只保存当下内存快照，不重新探测目标。自动验收覆盖部分异常、容量、原生窗口消息更新和 UTF-8 文件读回；真实提供者与 IME 仍待 UAT。

## 设置入口、快捷键及自启

“读取当前配置”上轮误保留，本轮删除；托盘重载及偏好开关也移除。两个快捷键字段只读，点击“录制”后按实际组合键，全部松开后完成；Esc、取消、离开或关闭窗口取消。只在明确录制期间启用 InputHook，不收集文本；业务快捷键临时注销，结束后按暂停/开关状态恢复。点击保存后生效；重复热键仍拒绝保存。

“开机自动启动”默认关闭，实际是当前用户登录后启动。在当前用户 Startup 目录维护带归属标记的 `Ime-2Chinese.lnk`；源码入口指向 AHK 与带引号的 main.ahk，保留当前普通/重喂/历史测试模式。保存失败回滚快捷方式；同名非本工具文件不覆盖。不自动提权、不创建后台服务。移动工程或更换 AHK 后需重新保存自启配置；Windows 设置中禁用启动项也会阻止启动。

设置关闭时不保存；重新打开读取最新配置并放弃旧草稿。旧文件/规则仅作兼容，用户修改偏好以窗口为入口。

## cmd 兼容判断

cmd 的行编辑由控制台宿主管理，所选屏幕文本不一定是可替换的当前输入行；传统控制台及 Windows Terminal 都需要专用边界识别、复制/删除及候选处理。终端 UIA 文本范围甚至会报告非只读，不能据此放行。当前明确跳过已知控制台/终端窗口，诊断记为 TerminalUnsupported，不声称已复现用户当时快捷键无响应的唯一原因。需求较低，暂不做终端重喂；若未来需要，作为独立兼容任务。

依据：[Windows Terminal 文本属性实现](https://github.com/microsoft/terminal/blob/main/src/types/UiaTextRangeBase.cpp)、[Chromium 只读判定](https://chromium.googlesource.com/chromium/src/+/HEAD/ui/accessibility/ax_node.cc)、[AHK 按键录制接口](https://github.com/AutoHotkey/AutoHotkeyDocs/blob/v2/docs/lib/InputHook.htm)。Windows 按应用记忆输入法由系统实现，与本工具按规则更改内部中英文状态不同；自动切换仍冻结。
