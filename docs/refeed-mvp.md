# 重喂 MVP 测试

目前是显式启用的测试版本，P2 的核心编排已实现，真实桌面重喂仍待验证。普通双击 `main.ahk` 继续只启动配置和托盘。测试受限时可以延后到最终 UAT，不阻塞独立模块开发。

## 启动

退出旧 `src/core.ahk` demo 和正在运行的主程序，再双击 `tests/refeed-mvp.ahk`；或运行 `main.ahk --test-refeed`。需要 AHK v2，使用自己的正常桌面账户。该入口加载同一个 App 和用户配置，托盘会标明“重喂测试版”；配置中的功能开关及热键仍有效。

先手动启用搜狗。MVP 暂未实现从英语键盘/日语激活指定搜狗；目标尚未启用或身份提示不符合配置时，保留原文并提示。不会使用 Q11 中待确认的会话级激活。

## 最小操作

1. 在空白记事本或 `tests/browser-input.html` 输入 `ni hao`，确保当前没有未提交的候选/组合文本；先切到搜狗英文，再选中完整文字。
2. 按 `Alt+Z`。程序复制并校验选区，确保中文，再复制检查选区仍完整，之后删除并逐字符重喂。只在候选状态停下，由你选词。
3. 选词后，在另一处或另一窗口按 `Alt+Shift+Z`，应插入完整的 `ni hao`；可以重复取回。
4. 用数字、标点、纯空白或超长文本尝试拒绝路径，原文应保留，之前的有效缓存也应保留。

菜单可暂停/恢复、修改功能偏好、打开/重载配置及退出。若之前关闭了 EnableRefeed，请用托盘启用。退出清空原文缓存；只运行一份输入功能脚本。自动切换尚未接入。

## 已实现的保护

- 长度在去空白前计算，默认上限 50，保留大小写及全部原文空白；默认发送间隔 10ms。
- 复制等待有界；热键修饰键未释放、焦点未知/变化、文本非法、中文确认失败或二次选区不一致，在删除前退出。
- 共享重入锁；删除/发送中出错或目标变化，停止发送并保留缓存供取回，不向新窗口回滚。
- 剪贴板备份全部格式；按序列号跟踪本工具的数据，外部更新时保留新内容。复制来源进程无法确认时拒绝。统一清理路径及退出清理释放备份。
- 取回通过 SendText 在当前目标插入，不取消候选，不清除之前重喂结果，不接管 Ctrl+Z。
- 日志只包含事件及原因编号，不包含选区、缓存或完整标题。

## 待验收的范围

已有候选/组合文本的自动检测尚未可靠实现，测试入口只用于无候选的人工样例。传统控件句柄不能保证区分 Chromium 同窗内的不同网页输入框，二次复制只验证选区文本一致，不能证明网页控件身份相同；这两项需要后续底层研究/UAT，不宣称已经保护所有编辑状态。

指定输入法激活、权限差异、复制来源进程在不同浏览器中的表现、已有候选时取回的应用副作用，以及正常入口默认启用，均待后续验证。未测试能力不作为日常使用承诺。

记录结果时注明应用/版本、输入法版本、选区文本（仅人工样例）、起始模式、提示和实际候选/输入效果；可写入本地 REVIEW_QUEUE 或聊天。字段解释见 [诊断说明](ime-diagnostics.md)，阶段策略见 [测试方案](testing-strategy.md)。
