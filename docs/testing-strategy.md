# 测试方案

更新：2026-10-04。目标：自动检查覆盖日常改动，真实桌面验证集中进行，不要求每个开发步骤都操作桌面。

## 环境分工

- **沙箱**：AHK 加载、纯逻辑、配置与规则、注入故障后的编排测试。不将沙箱内的 IME 枚举结果当作真实用户输入法配置。
- **真实桌面用户**：搜狗/微软实际启用、编辑框焦点、模式切换、候选与剪贴板行为。使用普通用户上下文运行测试源码或 exe；高权限应用另做专项测试。
- **computer-use**：可以在真实测试窗口里执行少量验证，按 Esc 会结束当轮桌面操作；也可以由用户自己执行短清单，不依赖远程接管。

本机已观察到沙箱枚举与普通桌面用户的枚举不同，后者能枚举已启用搜狗和微软拼音。Codex Windows 沙箱可以使用专用用户，并默认使用私有桌面；因此给沙箱用户安装/启用搜狗至多解决一部分用户配置问题，不能据此保证能控制日常用户的编辑框。

不为测试专门安装输入法到沙箱账号，不修改全局 Codex 沙箱设置。真实桌面测试在已有搜狗的日常用户环境完成。

## 三层验证

| 层次 | 时机 | 内容 | 执行者 |
| --- | --- | --- | --- |
| 自动测试 | 每个相关功能点 | AHK 加载；文本边界；规则顺序；配置读写；未知状态；超时/失败/焦点变化等流程 | Codex |
| 最小桌面验证 | P2 重喂 MVP 可运行后，或用户自愿提前检查；环境受限时延后 | 搜狗状态读取和中英文设置；一次重喂候选；一次取回 | 用户或获准继续的 computer-use |
| 集中 UAT | 主要功能完整后，P6 发布前 | 浏览器/记事本、自动切换、手动选择、剪贴板、候选、输入法激活、微软对照；最后检查 exe | 用户为主，Codex依据记录修复 |

模拟测试只能证明流程，不能证明第三方 IME 兼容。计划采用可注入的系统适配层，自动验证失败时不删除、停止发送和不覆盖手动选择等关键约定；对断言只重复实现的测试不作无意义扩展。

P0 分为“诊断与控制代码”及“真实兼容性验收”。真实兼容结果尚未齐全时，允许继续 P1、P2 的编排和 P3；未验收的写入路径仅在显式测试下启用，不能标为已验证，也不能作为日常使用默认能力。

不必为了首次验证先打包 exe，AHK v2 源码可以直接运行。界面、长时间试用、更多失败情形和打包差异集中到 UAT；建议在重喂 MVP 出来时先验证核心路径，避免直到全部完成才发现底层控制方式不适用。

用户已确认：若后续 computer-use 仍难以取得有效桌面结果，可以跳过 MVP 的核心桌面验证，继续开发并等待最终 UAT。先前已给约十分钟但未取得有效结果，不再把再次接管桌面作为推进门槛；未验证项保持明确标注。

自动检查入口为 `tests/run-tests.py`，用 Python 运行；它调用本机 AHK v2，各检查有十秒超时，同时检查输出，避免把 AHK 启动错误的退出码 0 误判为成功。生命周期集成检查在任务临时目录生成配置、创建托盘、注册并注销少用热键；不输入文本，不调用 IME 写入接口。Python 只用于开发检查，不作为常驻程序依赖。

P3 增加固定上下文规则测试、隐藏自有窗口读取测试和 App 规则重载故障测试。覆盖非字母顺序的 Ignore 例外、同规则标题刷新、同动作不同编号、规则重排/定义修改、未知标题不越过例外、注册/保存失败保留有效规则。窗口测试不激活窗口、不注入文本、不写 IME；自动监听行为仍由 P4 测试和最终 UAT 验收。运行器显式指定 AHK 启动错误的 UTF-8 编码，并避免控制台无法编码诊断字符时中断检查；接口依据 [AHK 命令行说明](https://github.com/AutoHotkey/AutoHotkeyDocs/blob/v2/docs/Scripts.htm)。

## 用户现在是否需要操作

**现在没有必须完成的用户操作，可以继续开发。**

如果愿意提前用约 3–5 分钟确认模式控制，可在自己的普通桌面账户双击 `tests/ime-smoke.ahk`（需要已安装的 AHK v2），然后打开空白记事本和浏览器测试页 `tests/browser-input.html`。

只在空白编辑区测试，确保当前启用搜狗，点击编辑框，然后：

1. 手动切到搜狗英文模式，按 `Ctrl+Alt+F8`，记录提示是否为 English。
2. 手动切到搜狗中文模式，再按 `Ctrl+Alt+F8`，记录是否为 Chinese。
3. 按 `Ctrl+Alt+F9` 设置中文，再按一次，观察没有翻转；按 `Ctrl+Alt+F10` 设置英文，再按一次，观察没有翻转。
4. 在记事本和浏览器各做一次，记录实际输入法状态是否与提示一致；提示失败也是有效结果，不需自行修复。
5. 用 AHK 托盘退出该测试脚本，把 `logs/ime-smoke.log` 的相关结果和实际观察写入本地 REVIEW_QUEUE，或直接在聊天反馈。

脚本不复制、不删除、不发送文本，不激活其他输入法，也不做会话级切换。日志不含输入内容或窗口标题，留在已忽略的本地 logs 目录。`profileHint` 是 TSF 上下文提示，不是目标窗口身份已可靠验证的声明；用户实际观察也是验收证据的一部分。

原有 CLI `--mode ... HWND` 要求目标仍在前台，直接从终端运行容易因为终端抢焦点而拒绝；热键工具用于解决这个测试操作问题。

## 重喂 MVP 与集中 UAT

重喂 MVP 到位后由 Codex提供可运行版本及短清单。最低验证：浏览器空白输入框内，搜狗英文模式下选中 `nihao`，触发重喂并看到候选；由用户选词，再在另一处取回原文。重复一次即可发现最关键的底层兼容问题。

当前已提供 `tests/refeed-mvp.ahk` 显式测试入口，具体步骤和未验收范围见 [MVP 说明](refeed-mvp.md)。用户首轮 smoke 已记录读取及切中文符合实际、旧切英文失败；smoke v2 修正代码待复测，字段解释见 [诊断说明](ime-diagnostics.md)。未自动激活指定搜狗时，不删原文；无候选的前置条件及 Chromium 同窗焦点限制仍待完整验证。

集中 UAT 按 `tests/manual-checklist.md` 执行：先用搜狗跑浏览器和记事本的核心流程，再做微软拼音对照；测试指定输入法激活、规则变化与手动选择、复制/图片等剪贴板内容、失去焦点、候选状态、暂停恢复和最终 exe。现阶段不启动 VS Code。

输入法激活的会话级后备方案另在 REVIEW_QUEUE 讨论；当前 `--activate-session` 仅为显式实验入口，不放进用户默认测试或生产自动切换。
