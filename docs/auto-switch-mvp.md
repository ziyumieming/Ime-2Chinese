# 自动切换与全功能 MVP

P4 已实现自动监听、规则变化判断与重喂互斥，真实桌面自动行为待 UAT。普通 `main.ahk` 和仅重喂入口不启用监听。

退出旧功能脚本，双击 `tests/features-mvp.ahk`，或运行 `main.ahk --test-all`。托盘显示“全功能 MVP 测试”。使用自己的桌面账户；默认配置没有规则。按需从 [规则示例](rules.md) 复制少量规则到用户配置，再重载；Chrome 的进程名是 `chrome.exe`，Edge 示例不能直接匹配 Chrome。

## 预期行为

- 启动、恢复、重新启用时评估当前窗口一次；进入或再次返回窗口按第一条命中设置模式。
- 定时检查仅用于发现变化，不是每轮设置模式；当前尚未改用原生窗口事件。Issue #3 中“轮询立即切回”的旧表述已澄清，重喂结束会记住匹配，普通后续检查不会切回。
- 标题规则变化到另一条命中时应用新动作。同规则标题刷新、规则位置移动和无关配置改动不重复设置，保留手动选择。
- Ignore 和无匹配不操作。只设置当前可观察中文输入法内部模式，不换输入法；其他语言布局跳过。
- 失败或异常在当前窗口/当前命中期间不循环重试；新的窗口进入或有效规则变化才再次尝试。轮询不读取当前模式来持续纠正。
- 重喂/取回与自动操作共用互斥锁。重喂结束先记录当前匹配，再恢复轮询，不立即改回自动英文规则。
- 重喂已删除原文时，保护原目标窗口的本次停留：标题变化、重载和暂停恢复都不改模式，离开后再按规则工作。候选结束检测尚未可靠实现，保护可能长于选词过程；恢复边界在 [Issue #3](https://github.com/ziyumieming/Ime-2Chinese/issues/3) 讨论。
- 暂停/关闭自动切换停止计时器；重载可改变间隔；保存或计时器应用失败回退有效配置；退出清理计时器及热键。

## 最小试用

用记事本或浏览器人工页面配置一条明确规则，切入窗口观察一次设置，随后手动改模式并停留，确认不会被轮询改回。离开再返回应重新设置。添加具体标题例外后，检查切到另一条规则和同规则标题刷新。最后在英文规则窗口内重喂，确认候选不被后台改成英文，并试暂停/恢复。

监听间隔由 `PollIntervalMs` 控制，默认 300ms；在两次轮询之间发生并结束的极短窗口切换可能不被观察。首版不做网址或输入框级规则。真实搜狗/微软、候选、空闲长时间运行和权限差异集中验收；自动测试验证事件判断、故障及原生计时器清理，没有代替桌面测试。
